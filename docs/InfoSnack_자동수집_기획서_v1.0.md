# InfoSnack 자동 수집(커스텀 소스) 기획서

> 작성일: 2026-06-05
> 버전: v1.0
> 비고: 기존 InfoSnack PRD v1.0의 고도화 항목 **'자동 구독'(고도화 1순위)** 을 구체화한 기능 기획서입니다.

---

## 1. 기능 개요

### 1.1 기능 소개
- **기능명**: 커스텀 자동 수집 (Custom Auto-Collection)
- **한 줄 소개**: 사용자가 원하는 정보 소스를 직접 등록해두면, 정해둔 주기마다 시스템이 알아서 새 콘텐츠를 모아오는 기능
- **기능 목적**: 기존엔 사람이 매번 링크를 넘겨야만 정보가 쌓였지만, "한 번 등록해두면 알아서 쌓이는" 능동적 수집을 추가한다.

### 1.2 해결하고자 하는 문제
현재 InfoSnack은 **사람이 직접 링크를 넘길 때만** 콘텐츠가 들어온다. 브라우저 확장, 모바일 공유, 슬랙 봇 세 가지 모두 누군가의 행동이 있어야 동작한다.

이 구조에는 두 가지 한계가 있다.
- 좋은 글을 발견하고도 넘기는 걸 잊으면 그대로 누락된다.
- 매일 챙겨보는 출처(블로그, 뉴스레터, 특정 계정)도 매번 손으로 가져와야 한다.

**해결책**: 자주 보는 출처를 한 번 등록하면, 주기마다 자동으로 새 글을 수집해 기존 InfoSnack 처리 과정(요약·태깅·검색·챗봇)에 그대로 합류시킨다.

## 2. 타겟 사용자

### 2.1 주요 사용자
기존 InfoSnack 사용자인 **AI Agent 팀(5~6명)** 전원. 팀원 누구나 수집처를 자유롭게 등록·관리할 수 있다.

### 2.2 사용자 유형별 정의
| 사용자 유형 | 설명 | 주요 권한/기능 |
|------------|------|---------------|
| 일반 사용자 (전 팀원) | 별도 역할 구분 없음 | 수집처 추가·편집·일시중지·삭제 모두 동일하게 가능 |

> MVP에서는 역할을 나누지 않는다. 수집처는 모두 팀 공용 라이브러리로 유입된다.

## 3. 핵심 기능

### 3.1 기능 목록

| 우선순위 | 기능명 | 설명 | 관련 사용자 |
|---------|-------|------|------------|
| P1 (필수) | 수집처 추가 (계층형) | 주소를 붙여넣어 새 소스를 등록 | 전 팀원 |
| P1 (필수) | 소스 종류 자동 감지 | 주소를 보고 유형 판단 후 기본값 적용 | 전 팀원 |
| P1 (필수) | 자동 수집 실행 | 사용자가 정한 주기마다 새 항목만 수집 | 전 팀원 |
| P1 (필수) | 수집처 관리 | 등록 소스 목록·상태 확인, 일시중지·편집·삭제 | 전 팀원 |
| P2 (권장) | 추출 고급 옵션 | 특정 영역만, 링크 따라가기(depth) 등 | 전 팀원 |
| P2 (권장) | 고급 레시피 직접 지정 | 까다로운 사이트용 세밀한 규칙 작성 | 고급 사용자 |
| P2 (권장) | 수집 실패 알림 | 반복 실패 시 자동 일시중지 + 알림 | 전 팀원 |

### 3.2 기능 상세

#### 3.2.1 수집처 추가 (계층형)
- **설명**: 새 정보 소스를 등록하는 핵심 화면. 처음 화면은 **주소 입력칸 하나**만 보인다.
- **동작 방식**: 사용자의 숙련도에 따라 3단계로 깊이가 나뉜다.
  - **1단계 — 그냥 붙여넣기 (대부분 여기서 끝)**: 주소를 붙이면 시스템이 종류를 자동 감지하고 합리적인 기본값을 적용한다. 기본 추출은 **'전체 본문'** 이다.
  - **2단계 — 핵심 옵션 조정**: '옵션'을 펼치면 본문 범위, 수집 주기, 자동 태그를 조정할 수 있다.
  - **3단계 — 고급 레시피 (P2)**: 까다로운 사이트를 위해 가져올 영역 등을 직접 지정한다.
- **입력**: 소스 주소(URL), (선택) 옵션값
- **출력/결과**: 수집처 등록 + 즉시 1회 시범 수집으로 **미리보기** 제공 (제대로 들어오는지 저장 전에 확인)
- **예외 상황**: 종류를 못 알아보면 '일반 웹페이지'로 처리하고, 접근이 안 되면 안내 메시지를 보여준다.

#### 3.2.2 소스 종류 자동 감지
- **설명**: 붙여넣은 주소를 보고 어떤 유형인지 판단해 친화적인 기본값을 적용한다.
- **동작 방식**: RSS면 피드 항목을, 계정형(X·LinkedIn·Reddit 등)이면 새 게시물을, 일반 페이지면 본문을 기준으로 기본 설정을 맞춘다.
- **출력/결과**: 감지 결과를 화면에 표시 (예: "RSS 피드로 인식했어요")
- **예외 상황**: 사용자가 감지 결과를 수동으로 다른 종류로 바꿀 수 있다.

#### 3.2.3 추출 옵션 (어떻게 가져올지)
- **본문 범위**: 전체 본문(기본) / 요약만 / 특정 영역만(고급)
  - → "RSS가 요약만 줄 때 본문까지" 요구사항은 **전체 본문이 기본값**이라 별도 설정 없이 해결된다.
- **링크 따라가기(depth)**: 본문 안의 링크까지 가져올지 여부 (기본값: 해당 항목만)
- **자동 태그**: 이 소스로 들어오는 콘텐츠에 자동으로 붙일 태그를 미리 지정

#### 3.2.4 자동 수집 실행
- **설명**: 등록된 주기마다 소스를 확인해 **새 항목만** 가져온다.
- **동작 방식**: 사용자가 정한 주기(예: 매시간 / 하루 1회 / 직접 입력)마다 소스를 확인 → 마지막 확인 이후 올라온 새 글만 수집 → 이미 수집한 항목은 건너뛴다.
- **입력**: 수집 주기 설정
- **출력/결과**: 새 콘텐츠가 라이브러리에 추가된다.
- **예외 상황**: 과도하게 잦은 주기를 막기 위한 최소 간격 가이드를 둔다. 수집 실패 시 3.2.6의 실패 처리로 이어진다.

#### 3.2.5 수집된 콘텐츠 처리 (기존 흐름 합류)
- **핵심**: 자동 수집된 항목은 별도 저장소가 아니라 **기존 InfoSnack 처리 과정에 그대로 들어간다.** 즉 이미지 분석·OCR → AI 요약·태깅 → 썸네일 생성 → 검색 등록 → 지식 그래프까지 동일하게 처리된다.
- **결과**: 사용자 입장에서 "사람이 넘긴 콘텐츠"와 "자동 수집된 콘텐츠"가 똑같이 보이고, 검색과 챗봇에 함께 잡힌다.
- **출처 표시**: 자동 수집된 항목은 어떤 수집처에서 왔는지 표시한다.

#### 3.2.6 수집처 관리
- **설명**: 등록한 수집처를 한눈에 보고 관리하는 화면.
- **동작 방식**: 소스 목록 / 마지막 수집 시각·상태 / 최근 수집 건수 표시, 각 소스를 일시중지·재개·편집·삭제할 수 있다.
- **실패 처리**: 사이트 구조 변경 등으로 수집 실패가 반복되면 해당 소스를 **자동 일시중지**하고 사용자에게 알린다.
- **중요도**: 누구나 소스를 추가하므로 중복·방치된 소스가 쌓이기 쉽다. 이 관리 화면이 품질 유지의 핵심이다.

#### 3.2.7 고급 레시피 (P2)
- **설명**: 까다로운 사이트를 위한 선택 경로. 가져올 영역을 직접 지정하는 등 세밀한 규칙을 작성한다.
- **대상**: 특정 영역만 추출해야 하거나 구조가 특수한 사이트.
- **위치**: 일반 사용자는 거의 사용하지 않으며, 고급 사용자만 들어오는 옵션이다.

## 4. 사용자 시나리오

### 4.1 핵심 시나리오

**시나리오 1: 자주 보는 블로그 자동 수집**
> 사용자: 팀원 누구나
> 목적: 매일 챙겨보는 AI 블로그를 자동으로 라이브러리에 쌓기

1. '수집처 추가'에서 블로그 주소(또는 RSS 주소)를 붙여넣는다.
2. 시스템이 'RSS'로 자동 감지하고 전체 본문 기본값을 적용한다.
3. 미리보기로 최근 글이 제대로 들어오는지 확인한다.
4. 주기를 '하루 1회'로 설정하고 저장한다.
5. 이후 매일 새 글이 자동 수집되어 검색·챗봇에 함께 잡힌다.

**시나리오 2: 요약만 주는 뉴스레터의 본문까지 수집**
> 사용자: 팀원 누구나
> 목적: 요약만 오는 출처에서 원문 본문까지 확보하기

1. 뉴스레터 RSS 주소를 등록한다.
2. 본문 범위가 '전체 본문'(기본값)인지 확인한다.
3. 저장하면 이후 요약이 아닌 **원문 본문**까지 수집된다.

**시나리오 3: 특정 계정의 새 글 자동 수집**
> 사용자: 팀원 누구나
> 목적: 특정 인물의 글을 놓치지 않기

1. X 또는 LinkedIn 계정 주소를 붙여넣는다.
2. 계정형 소스로 자동 감지된다 (기존 로그인 세션을 활용해 접근).
3. 주기를 설정하면 새 게시물이 올라올 때마다 자동 수집된다.

**시나리오 4: 수집 실패 처리**
> 사용자: 팀원 누구나
> 목적: 잘 되던 소스가 깨졌을 때 인지하기

1. 한동안 잘 되던 소스가 사이트 개편으로 수집에 실패한다.
2. 시스템이 해당 소스를 자동 일시중지하고 알림을 보낸다.
3. 사용자가 관리 화면에서 상태를 확인하고 수정·재개한다.

## 5. 화면 구성 (개요)

### 5.1 주요 화면 목록

| 화면명 | 설명 | 주요 요소 |
|-------|------|----------|
| 수집처 추가 | 새 소스를 등록 | 주소 입력칸, 자동감지 결과, (펼침) 옵션, 미리보기, 저장 버튼 |
| 수집처 관리(목록) | 등록 소스를 한눈에 관리 | 소스 목록, 상태·마지막 수집 시각, 일시중지/편집/삭제 |
| 라이브러리·검색·챗봇 (기존) | 변경 없음 | 자동 수집분이 기존 콘텐츠와 자연스럽게 섞여 표시 |

### 5.2 화면 흐름 (간략)
라이브러리 → '수집처 추가' → 주소 붙여넣기(자동 감지) → (필요 시 옵션 조정) → 미리보기 → 저장 → 수집처 관리 목록에 등록

이후 백그라운드에서 주기마다 자동 수집 → 새 콘텐츠가 라이브러리에 등장

## 6. 용어 정의

| 용어 | 정의 |
|-----|------|
| 수집 소스 (소스/수집처) | 사용자가 등록하는 자동 수집 대상 (블로그, 뉴스레터, 계정 등) |
| 자동 감지 | 주소를 보고 소스 종류를 판단하는 기능 |
| 본문 범위 | 콘텐츠에서 어디까지 가져올지 (전체 / 요약 / 특정 영역) |
| 수집 주기 | 소스를 얼마나 자주 확인할지 |
| 신규 항목 | 마지막 확인 이후 새로 올라온 콘텐츠 |

## 7. 추가 고려사항

### 7.1 MVP 이후 확장 고려 기능
- **고급 레시피(3단계)**: 일정이 빠듯하면 후속으로 분리 가능. 1·2단계만으로도 일반 웹페이지는 전체 본문이 수집되므로, 대부분의 출처는 MVP 범위에서 커버된다.
- **공용/개인 소스 분리**: 기존 PRD의 '라이브러리 분리' 고도화와 연동.
- **소스 추천 / 공유·복제**: "이 출처도 등록해보세요", 팀 내 인기 소스 공유.
- **키워드 기반 수집**: 특정 키워드가 포함된 글만 수집, RSS 외 더 많은 자동 소스 타입 추가.

### 7.2 제약사항 및 전제조건 *(★ 확인 필요)*
- *(★)* 자동 수집된 항목도 기존 InfoSnack 처리 과정을 **그대로** 탄다는 전제로 설계함.
- *(★)* 로그인이 필요한 소스(X·LinkedIn 등)는 기존 로그인 세션 활용 방식을 재사용함.
- *(★)* 누구나 수집처를 추가 → **팀 공용 라이브러리**로 유입 (MVP는 단일 공용 라이브러리).
- *(★)* 수집 주기 **최소 간격 가이드** 필요 (과도한 확인 방지) — 구체 수치는 팀과 협의.
- *(★)* 수집 실패가 반복되면 **자동 일시중지 + 알림** (제안값).
- *(★)* MVP 범위 컷: 고급 레시피(3단계)는 P2로 두고 1·2단계 우선 출시 — 확정 필요.
